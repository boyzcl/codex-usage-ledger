# 第一轮实施与验收

范围：账本正确性、默认估算限制、旧账本隔离修复预览。基线为 `7c08aa866fa7994735a99de99ead9ceb544047fc`。第一轮实现与预览阶段只在独立克隆和账本副本中操作。验收后的部署作为单独阶段执行；部署方法见 [部署与恢复](DEPLOYMENT.md)，私人部署证据不入库。

## 必过验证

| 对象 | 方法与预期 |
| --- | --- |
| Legacy 分叉 | 父先、子先、分批、延迟父和重复同步最终均为 123；父缺失时保留待核对事实；分叉后的偶然相等不删除 |
| 文件检查点 | 同 inode 增长重写、中间变化、替换、截断增长均重解析；合法追加、半行、归档移动不重计；读取中变化不提交 |
| 设置 | 完整快照省略或空值清除旧 tier/effort；reroute 只更新提供的字段 |

| 旧账本修复 | 同 ID 归因可纠正、Token 事实不变、重复运行幂等；缺源历史保留并标记；合成副本演练备份、差异和回滚 |
| 集成 | `npm run check` 通过；真实一致性副本只预览，私人报告不入 Git |

## 实施顺序

1. 将独立复现转为可失败的回归测试，保存基线失败证据。
2. 修复分叉重核、完整前缀摘要与原子检查点、设置替换语义和完整快照链回退检测。
3. 收紧默认容量展示，保留显式实验入口和严格原因。
4. 实现有版本的隔离修复：一致性备份、重新解析、证据差异、幂等应用和回滚；不以重估价格替代历史金额。
5. 完成合成演练、真实副本预览、具体失败路径自审与最终检查，提交本地代码并形成交接记录。

## 后续轮次

账号/工作区与额度窗口归属、官方可用状态、完整 7/30 天范围、不可变价格版本替代关系；协议兼容、CI 和性能优化。未核实账号/窗口归属的经验外推不作为已验证套餐容量。

## 实施结果

- 已实现：延迟父历史的持久候选与重核、ordinal 分叉边界、完整前缀摘要与读取中变化回滚（含恢复 mtime 的同大小改写）、设置完整快照替换、包含单点的跨日快照链检查、默认未知容量和显式实验入口、版本化副本修复与备份回滚。
- `npm run check` 通过。针对本轮的回归包含 23 项；关键值断言见 `test/round1.test.ts`、`test/repair.test.ts` 和 `test/cli-round1.test.ts`，不以总测试数代替验收。
- 基线测试证明：子先为 243 而非 123；增长重写仅保留 1 条新记录而非 2；快照残留 Fast；跨日单点回退仍估计 1000；替换文件重解析的同 ID 归因仍为 a 而非 b。修复后这些反例均通过。
- 合成演练：原可见总量 442，修复后 322（排除继承 120）；同 ID 的 100 Token 保持不变，归因纠正；缺源 99 保留。重复修复无新增纠正或排除，回滚记录与原基线逐项一致。
- 对抗自审补足：重写不能丢弃待核对候选；重复重建保留缺源候选；compaction 恢复不能降级 provider 事实；Token 冲突保留旧事实并报告待核对；纠正事务中断回滚数据与版本；备份及输出目录以独占创建拒绝覆盖。
- 真实账本仅通过 SQLite 只读一致性备份分析，预览完成；具体日期/模型差异与私人数量保存在执行会话交接文件，未加入 Git。生产源代码、构建产物、全局 cux 和服务未切换。

## 现有限制

缺少父历史或起始对应关系的 legacy 候选仍待核对。旧日志没有 ordinal 分叉边界时，连续指纹只能提供有限的重放证据；损失的源、旧基线缺口和无法判定的归属不凭空恢复。缺源可见历史以独立标记保留，不代表已经重新核实。读取前后变化会整文件回滚并延后，持续写入的大文件可能需要后续重试。

变化文件多做两次完整摘要读取；本轮已测量真实扫描开销，性能优化留待后续。修复源在数据库备份后逐文件读取，新增记录可能包括备份后的正常活动。严格估算仍缺账号/工作区/窗口归属；显式经验入口也不消除此限制。价格替代、官方可用状态、完整 7/30 天范围、协议版本兼容矩阵、CI 和部署尚未实施。

## 独立验收后的收尾

原会话独立复跑第一轮检查和合成回滚后，发现 Node 支持范围未说明修复 API 的新增版本。本次保留普通查询/导入的 Node 22.13 下限，修复与回滚在任何输出创建前检查 `node:sqlite.backup`；缺失时明确报错，不留下空备份或输出目录。公开文档同时说明 Node 22 系列的最低修复版本为 22.16.0。

使用经官方 SHASUMS256 校验的 macOS arm64 Node 22.13.0 和 22.16.0 实测：22.13 的普通功能及无输出拒绝路径通过，4 项备份成功路径测试明确跳过；22.16 的完整测试、类型检查、lint 和备份/纠正/重复/回滚演练通过。当前 `npm run check` 为 104 项全通过，22.16 也为 104 项全通过；22.13 为 100 项通过、4 项跳过。这些范围不同，不把普通功能验证当作旧运行时支持修复的证明。

真实预览收尾只读取现有基线和修复副本，重新核对可观察的父候选、边界过滤、起始指纹关系以及六项 Token 事实。报告区分无父候选与有父候选但未建立起始匹配，不能笼统称为父日志缺失；候选/证据与基线的事实比较通过。私人聚合及可复核分析脚本位于执行会话，未加入 Git；本次未扫描源日志或改动去重算法。
